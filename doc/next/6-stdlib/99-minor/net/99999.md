The [net] package gains support for the Stream Control Transmission Protocol
(SCTP) on Linux and FreeBSD through the new `"sctp"`, `"sctp4"`, and `"sctp6"`
networks. [SCTPAddr] and [SCTPMultiAddr] describe single- and multi-homed
endpoints; [ResolveSCTPAddr] and [ResolveSCTPMultiAddr] parse them.

[DialSCTP], [DialSCTPInit], and [DialSCTPMulti] open one-to-one associations,
while [ListenSCTP], [ListenSCTPInit], [ListenSCTPMulti], [ListenSCTPMultiInit],
and [OpenSCTP] create one-to-many sockets. The resulting [SCTPConn] implements
[Conn] and [PacketConn], and additionally exposes per-message stream, payload
protocol identifier, and flag metadata through [SCTPConn.ReadFromSCTP] and
[SCTPConn.WriteToSCTP] using [SCTPSndInfo] and [SCTPRcvInfo].

[SCTPConn] also offers the common socket controls: association initialisation
([SCTPInitOptions]), Nagle, retransmission timers ([SCTPRTOInfo]), delayed
acknowledgements ([SCTPDelayedSackInfo]), partial reliability ([SCTPPRInfo],
[SCTPPRPolicy]), authentication ([SCTPAuthKey]), stream reset and stream
scheduling ([SCTPScheduler]), event subscription ([SCTPEventMask]),
multihoming address management, association status ([SCTPAssocStatus]), and
peeling an association off a one-to-many socket with [SCTPConn.PeelOff].

On other operating systems every SCTP entry point returns an error reporting
that SCTP is not supported.
